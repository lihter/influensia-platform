# Influensia Sourcing Platform — Runbook

How to install, seed, run, test and operate the platform on a laptop, and what changes when it moves to hosted Postgres / R2 / Resend. Architecture and module APIs: `docs/FOUNDATION.md`. Product: `docs/SPEC.md`.

---

## 1. Fresh laptop

| Need | Version | Notes |
|---|---|---|
| Node.js | **22+** (tested on 22.22) | `node -v`. Nothing else: no Docker, no Postgres, no Redis. PGlite (Postgres compiled to WASM) runs in-process. |
| npm | 10+ | If `npm install` crashes (a known npm 10 bug on this lockfile) use `npx npm@12 install`. |
| Git | any | |
| Playwright Chromium | for e2e only | `npx playwright install chromium` once on a laptop. In the build container it is preinstalled at `/opt/pw-browsers` (the config sets `PLAYWRIGHT_BROWSERS_PATH`); do **not** run `playwright install` there. |

Disk: ~1 GB for `node_modules`, ~60 MB per seeded data dir.

## 2. Install, seed, run

```bash
git clone <repo> influensia-platform && cd influensia-platform
npm install                       # or: npx npm@12 install
cp .env.example .env.local        # then set BETTER_AUTH_SECRET (openssl rand -hex 32); BETTER_AUTH_URL=http://localhost:3000
npm run db:seed                   # wipes ./.data, migrates, loads the SPEC §7 dataset, verifies it (~10 s)
npm run dev                       # http://localhost:3000
```

- **PGlite is single-process.** Stop `npm run dev` before `db:seed` / `db:reset` / `outbox:drain`, or they will fight over `./.data/pglite`.
- Next 16 refuses a second `next dev` in the same directory (`.next/dev/lock`). If a dev server is stuck: `pkill -f "[n]ext dev"; pkill -f "[n]ext start"` (the `[n]` stops pkill from matching your own shell).
- Production mode locally: `npm run build && npm start`.
- `BETTER_AUTH_URL` must equal the origin you serve on, port included — otherwise every auth POST is `403 INVALID_ORIGIN`.

## 3. Data

| Path | What | Reset |
|---|---|---|
| `./.data/pglite/` | the database | `npm run db:reset` (= `rm -rf .data && npm run db:seed`) |
| `./.data/files/` | uploads: `org/{orgId}/{entity}/{entityId}/{client\|internal}/{uuid}.ext` | same |
| `./.data/outbox.log` | every "sent" email as one JSON line (local sender) | same |
| `./.data/e2e/`, `./.data/e2e-snapshot/` | Playwright's own seeded copy + its pristine snapshot | recreated by every `npm run test:e2e` |
| `docs/fixtures/` | files the seed writes for tests (sample PDFs/CSV) | regenerated by every seed |

`.data/` and `docs/fixtures/` are git-ignored — never commit them.

Emails: nothing is transmitted in local mode. `/ops/outbox` lists every queued notification; "Run worker now" (admin) drains pending rows into `outbox.log`. `GET /api/cron/outbox` does the same (Bearer `CRON_SECRET` when set).

## 4. Checks

```bash
npm run lint          # ESLint incl. the anonymity import boundary (client code may not import the supplier schema or ops modules)
npm run typecheck     # tsc --noEmit
npm run test:unit     # Vitest — 137 tests, ~10 s
npm run build         # next build (Turbopack)
npm run test:e2e      # Playwright — 42 tests: ~6 min against next dev; CI=1 npm run test:e2e builds and runs next start (~2.5 min)
```

E2E details:
- Uses port **3100** (`E2E_PORT` to change) and its own data dir, so it can run while you develop on :3000 — but not while another e2e run is active.
- The web server command seeds `.data/e2e`, snapshots it, and starts Next with `E2E_RESET=1`. Each spec file's `test.beforeAll(resetDb)` restores the snapshot through `POST /api/test/reset` (404 in any other environment), so files are independent; tests within a file are serial and build on each other.
- `tests/e2e/anonymity.spec.ts` (@critical) crawls every `/app` page and client file link for both client users and fails on any supplier identifier (canary `ZZLEAKTEST`, supplier names, contacts, `+86`, `Co., Ltd`, `有限公司`, platform domains, `SUP-`/`PO-` refs), checks cross-org 404s, and proves non-vacuity on `/ops`.
- One file: `npx playwright test tests/e2e/orders.spec.ts`. Traces of failures: `test-results/*/trace.zip` → `npx playwright show-trace <zip>`.

## 5. Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `BETTER_AUTH_URL` | `http://localhost:3000` | Must equal the served origin. |
| `BETTER_AUTH_SECRET` | dev fallback | **Required in production** (`openssl rand -hex 32`). Rotating it signs everyone out. |
| `DATABASE_URL` | unset → PGlite | Postgres connection string; switches the driver (§6.1). |
| `PGLITE_DIR` | `./.data/pglite` | PGlite data dir. |
| `FILES_DIR` | `./.data/files` | Local storage root. |
| `OUTBOX_LOG` | `./.data/outbox.log` | Local email sink. |
| `SEED_CLOCK` | unset → wall clock | Fixed "now" (ISO) for seeding/demos; every service reads time through `clock.ts`. |
| `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | unset → local disk | R2/S3 storage (§6.2 — adapter is a stub today). |
| `RESEND_API_KEY`, `EMAIL_FROM` | unset → local sender | Real email (§6.3 — sender not wired yet). |
| `CRON_SECRET` | unset | Bearer token for `/api/cron/outbox`. |
| `E2E_PORT` | `3100` | Playwright port. |
| `E2E_RESET`, `E2E_SNAPSHOT_DIR` | set only by `playwright.config.ts` | Enable `/api/test/reset`. Never set these in production. |
| `AUTH_RATE_LIMIT` | unset | `off` disables Better Auth's built-in limiter (production default: 3 sign-ins / 10 s per IP). Set only by `playwright.config.ts`. |

## 6. Moving to hosted infrastructure

### 6.1 Postgres (Neon / Supabase / RDS, Postgres 16)
1. Create a database; set `DATABASE_URL` (use the pooled URL on Neon — the client already runs with `prepare: false`).
2. `DATABASE_URL=… npm run db:migrate` applies `drizzle/*.sql` (both `app` and `supplier` schemas + Better Auth tables). Migrations also run at first `getDb()`, but running them in the deploy step makes a bad migration fail the deploy instead of the first request.
3. Optional demo data: `DATABASE_URL=… npm run db:seed` **truncates every table** and reseeds — never against production data.
4. Schema changes: edit `src/db/schema/*.ts` → `npm run db:generate -- --name <what>` → commit `drizzle/`. Never edit an applied migration.
5. The e2e snapshot/reset mechanism is PGlite-only; e2e always uses PGlite.

### 6.2 Cloudflare R2 (files)
Set `S3_BUCKET`, `S3_ENDPOINT` (`https://<account>.r2.cloudflarestorage.com`), `S3_REGION=auto`, keys. **Known gap:** `src/server/shared/storage/s3.ts` is a stub that throws — implement `put/get/copy/delete/exists/downloadUrl` with `@aws-sdk/client-s3` + presigner (ARCHITECTURE §6: downloads become a 302 to a 60 s presigned URL after the same `canReadKey` check). Key layout and the `/client/` vs `/internal/` rule stay the same; migrate existing files by copying `./.data/files/org/**` to the bucket root.

### 6.3 Resend (email)
Set `RESEND_API_KEY` and `EMAIL_FROM`. **Known gap:** the Resend sender and React Email templates are not written; `/api/cron/outbox` and "Run worker now" still use `localSender`. Implement `resendSender` next to `localSender` in `src/server/shared/outbox.ts`, wrap it in `withLeakGate(sender, await loadLeakSources(db))` (last-gate leak check on every `client_*` email), and pick it when `RESEND_API_KEY` is set. Schedule `/api/cron/outbox` every minute (Vercel Cron) with `CRON_SECRET`.

### 6.4 Vercel
Node runtime (not edge) for everything that touches the db; set the env vars above; add preview domains to Better Auth `trustedOrigins` if you use preview deployments; PGlite is not usable on serverless — `DATABASE_URL` is mandatory there.

## 7. Known gaps

- Invite landing `/invite/[token]` and password reset (tokens are stored; users sign in with the temp password and change it in Settings). Login throttling is only Better Auth's default per-IP limiter in production (3 sign-ins / 10 s), not the per-account lockout of AC-AUTH-07/08/09.
- R2 adapter and Resend sender are stubs (§6.2, §6.3).
- `X-Test-Clock` header (SPEC F-28) not implemented; only `SEED_CLOCK`. No background stale worker — staleness is computed live.
- SPEC 2.4 `/api/app/**` JSON routes are not built (pages use server components + actions), so the anonymity crawl covers pages and file links only.
- Ops "preview as client" exists for orders only.
- Dark theme tokens exist; no toggle.
- Supplier performance: `defect_rate` and `quote_accuracy` are not computed yet (orders count, on-time rate and last order are).
